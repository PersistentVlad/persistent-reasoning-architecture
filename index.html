02 / Architecture

Separate proposing
from persisting.

The broader architecture studies explicit authority over durable state. PR Light explores a smaller operational profile built around artifacts, a proposal filter and Git-backed persistence.

01 / PROPOSE

Capture an outcome

An agent or adapter submits a candidate decision, constraint, task, procedure or issue. A suggestion is not yet canonical knowledge.

02 / FILTER

Prepare a draft

In PR Light, an artifact filter checks proposal quality before a draft enters the persistence path. This lightweight filter is distinct from full governance.

03 / PERSIST & PROJECT

Carry state forward

Accepted artifacts are stored with inspectable Git history. A selected working-context view makes relevant state available to the next execution cycle.

Conceptual lifecycle based on the project documentation. Runtime behavior depends on the selected integration and configuration.

Is this a model or an agent framework?

Persistent Reasoning is an architectural research direction. PR Light is a supporting layer intended to integrate with agent systems through adapters; the language model remains an external inference component.

What gets persisted?

Concise reasoning outcomes: tasks, decisions, constraints, procedures and issues. The design focuses on structured, inspectable artifacts and selected working-context views.

What is ready today?

The public repositories contain the PR Light experimental prototype and focused architecture demonstrators. Full governance, broader integration and general performance conclusions require further implementation and evaluation.

How can I evaluate or contribute?

Start with the PR Light README and benchmark documentation for runtime experiments, or the architecture appendices for boundary demonstrations. Useful collaboration includes independent evaluation, adapter development and review of persistence and validation boundaries.
